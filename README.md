# story-writer-ai

## 專案目標
地端離線 AI 故事寫作助手——透過 RAG（檢索增強生成）技術，讓 AI 模仿指定文本的敘事風格生成新內容，全程不需連網。

## 技術架構
- **推論引擎**：LM Studio（本地端）
- **對話生成模型**：Qwen3 8B（Q4_K_M 量化）
- **Embedding 模型**：bge-m3（Q8_0 量化）
- **資料庫**：SQLite
- **檢索方式**：向量語意檢索（cosine similarity）

## 系統流程
1. 收集公版權文本，依段落切塊，存入 SQLite
2. 對每個段落計算 embedding 向量，存入資料庫
3. 使用者輸入場景描述 → 計算查詢向量 → 找出資料庫中語意最相近的段落
4. 將檢索出的段落作為風格範例，組成 prompt，交由 Qwen3 生成新內容

## 目前進度

### 語料庫
- 選定郁達夫（公版權，1945 年逝世）作品作為測試語料，風格特徵：第一人稱內省獨白、感官細節細膩、情緒層次豐富
- 收錄 3 篇短篇小說：《沉淪》《春風沉醉的晚上》《薄奠》
- 切塊後共 362 個段落，皆已完成 embedding

### 已驗證可行的功能
- ✅ 語意檢索：輸入現代白話（如「夜晚一個人喝酒，覺得很孤單」），能正確撈出用詞完全不同、但語意相符的段落（相似度 0.6+）
- ✅ 生成品質：關閉 Qwen3 思考模式（`/no_think`）後，生成速度與文風貼合度皆明顯提升
- ✅ 風格一致性：多次測試（雨天、桃子等主題）皆呈現一致的內省抒情文風，證明檢索確實在主導生成方向

### 已知問題
- **敘事斷裂**：部分生成結果會把檢索片段中的對話直接嫁接進新場景，缺乏語境一致性檢查（例如「數學考試」場景中出現與情境無關的母女對話）
- **段落合併瑕疵**：早期版本中，各篇文章的「標題+作者」行曾因段落切分規則誤判被存入資料庫，已透過位置過濾（濾除每篇第 0 段）修正

## 環境備註
- 開發過程中曾遭遇多重 Python 環境衝突（Anaconda 自動啟動 base、PATH 未即時載入），已排查解決，環境現在穩定

### 已解決的問題
- **敘事斷裂**：初版生成結果會把檢索片段中的對話直接嫁接進不相關的新場景（例如「數學考試」場景中出現無關的母女對話），導致敘事邏輯斷裂。修正方式：在 prompt 中加入明確指示「僅參考風格語氣，不挪用具體對話/人名/情節」，修正後經測試確認問題解決。
- **段落合併瑕疵**：早期版本中，各篇文章的「標題+作者」行曾因段落切分規則誤判被存入資料庫。已透過位置過濾（濾除每篇第 0 段）修正，並以自製測試文本驗證修正有效。
